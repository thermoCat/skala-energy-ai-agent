# HubCast

**주유소 복합 에너지 허브 전환 Agent** — Hub + Forecast, 어느 주유소를 어떤 에너지 허브로 바꿀지 미리 알려 줍니다.

SK에너지 서울 주유소에 **어떤 에너지(전기·수소 등)를 어디에 더할지** 공공 실데이터로 판단하는 멀티 에이전트 서비스와 관리자 대시보드.

![대시보드 첫 화면](assets/map.jpg)

## 1. 진행 사항 소개

### 과제 1 — 베이스 Agent에서 추가·수정한 Task

강의 베이스코드(운영 장애 대응 Agent)의 뼈대(FastAPI · LangGraph · MCP · SSE)를 유지하고 도메인과 각 단계를 바꿨습니다.

| 구분 | 베이스 (장애 대응) | HubCast |
|---|---|---|
| 요청 분류 | 일반 대화 / 장애 진단 | 일반 대화 / 주유소 진단 / 자치구 묶음 / 신설 시나리오 / 이름 찾기(되묻기) / 상시 작업 |
| MCP | Tool 1 · Resource(런북) 1 · Prompt 1 | Tool 15 · Resource(판정 기준) 1 · Prompt(자치구 진단) 1 |
| 게이트 | 계획에 끼어든 분석 작업을 코드로 제거 | LLM 판별이 최소 기준과 다르면 교정하고 "교정됨" 표시 |
| 재계획 | 런북이 없으면 장애 유형으로 조회 추가 | 자사 거점이 없는 구를 물으면 가장 가까운 구로 다시 계획 |
| 답변 작성 | LLM이 수집 사실로 직접 작성 | 숫자·출처 번호가 든 답변 뼈대는 코드가, 문장 다듬기는 LLM이 |
| 검증 | 30자 이상 + 번호 형식 (최대 3회) | 답변 숫자를 사실과 대조 + LLM 판정, 불합격 시 1회 재작성 |
| 저장 | 대화 이력 | 대화 + 판단 이력·사람의 결정·알림·작업 기록 |
| 화면 | 채팅 | 지도 대시보드 (핀·자치구 경계·정보 패널·채팅·알림함) |
| 추가 | — | 우선순위 AI 판단, 일간 추적, 주간 추적 |

### 과제 2 — 선정 주제와 주요 Task

**주제 선정 배경**

- 서울 1년 변화(2025.9 → 2026.9): 경유차 **−6.6%**, 전기차 **+43.2%** — 주유소가 갖출 에너지 구성이 지역마다 달라짐
- SK에너지 서울 주유소 114곳 중 주유소 안 충전기가 있는 곳은 **8곳**
- 충전 사업은 가동률이 수익을 가름 → 어느 주유소에 무엇을 넣을지 데이터로 판단 필요

**해결하려는 문제**

- 대상: 서울 25개 자치구, 주유소 397곳 + LPG 충전소 73곳 (SK에너지 130곳)
- 연료: 휘발유 · 경유 · LPG · 전기 · 수소
- 사용자: 리테일 네트워크 관리자, 투자 검토 담당자
- 문제: 수급 데이터가 여러 기관에 흩어져 있음, 충전기 신설 위치를 정할 자료 부족, 고장 충전기를 늦게 파악
- 원칙: 실데이터만 사용, 판별은 LLM · 최종 판정은 코드, 결정은 사람

**주요 Task**

| 기능 | 내용 |
|---|---|
| 주유소 진단 | 충전기 후보 판정과 이유, 반경 1km 급속충전기·경쟁 운영사 |
| 자치구 진단 | 충전기 부족, 경유·LPG차 감소 신호, 자사 주유소 묶음 |
| 우선순위 판단 | 충전기 후보가 2곳 이상이면 AI가 먼저 볼 곳과 이유를 판단, 코드는 후보·인용 사실·숫자만 검사 |
| 신설 시나리오 | "충전기 N대 신설하면?" 지표 변화 계산 |
| 이름 찾기 | 같은 이름 주유소가 여러 곳이면 되묻기 |
| 일간 추적 | 자사 주유소 1km 안 급속충전기가 직전 수집 정상에서 3회 연속 고장으로 바뀌면 멈춘 이유별 알림 |
| 주간 추적 | 자사 주유소 1km 안 급속충전기 신설·철거 보고, 새 충전기는 일반 이용·버스 전용 구분 |
| 대시보드 | 지도(470곳 핀, 자치구 신호), 정보 패널, 채팅, 알림함 |

## 2. 사용한 기술 요소와 구현 결과

### 기술 요소

| 요소 | 적용 |
|---|---|
| Multi-Agent | LangGraph Supervisor 아래 분석(판별·우선순위)·정책경쟁·작성·검증 에이전트. 조회·계산·기준 판정은 코드 |
| MCP | FastMCP 서버를 stdio로 연결. Tool 15개(수요·충전기·수소·주유소 카드·시나리오·이상 감지·경쟁 변화 등), Resource `criteria://energy-mix`, Prompt `district_review_prompt` |
| 의존성 주입 | `SupervisorDeps`(LLM 2개·MCP·저장소)를 `functools.partial`로 모든 노드에 주입. 테스트에서 가짜 LLM으로 바꿔 끼움 |
| LangSmith | 노드·LLM·MCP 호출에 `@traceable`, 요청 하나가 계층 트리로 기록 |
| 모듈화 | `agent/`(그래프·LLM·검증) · `energy/`(데이터·지표·판정 규칙) · `mcp_server.py` · `data_prep/`(수집) 분리, 기준값은 `energy/criteria.py` 한 곳 |
| 단위 테스트 | pytest 112개, 실데이터 스냅샷 사용 |
| 그 밖에 | SSE 단계 스트리밍, MCP 병렬 조회(`asyncio.gather`), 일시 오류 재시도, SQLite 저장 |

### 시스템 구조

```
질문 → 요청 분류 → MCP Tool 병렬 조회 → LLM 판별
     → 코드 기준과 비교 (다르면 교정) → 답변 작성
     → 숫자·인용 검증 (불합격 시 1회 재작성) → SSE로 화면 표시
```

- 일간·주간 추적은 코드가 먼저 변화 감지, 변화 없으면 LLM 호출 없음
- 사람의 결정은 `POST /api/decisions`로 저장, 에이전트는 읽기만 함

## 3. 향후 개선

### 어려움과 해결

| 어려움 | 해결 |
|---|---|
| 작은 모델의 판별이 사람이 정한 기준과 절반만 맞음 (일치율 53.7%) | 25개 구 순위 사실을 넣고 순위 읽는 법을 프롬프트에 적고, 판별에만 생각 모드 → 88.9% |
| 우선순위 기능을 붙이자 판별 입력이 길어져 일치율 77.8%로 하락 | 우선순위용 사실을 판별 입력에서 분리 → 85.2% |
| 8B 작성 모델이 숫자를 빼먹거나 뼈대에 없는 줄을 덧붙임 | 숫자·출처 번호가 든 답변 뼈대를 코드가 만들고, 뼈대 밖 줄은 잘라냄 |
| 검증이 주유소 번호(A0009172) 속 숫자를 데이터에 없는 숫자로 오인 | 주유소 번호·출처 번호·상호를 빼고 대조 |

### 한계

- 판매량·재고, 부지 적합성, 투자 수익 예측, 서울 외 지역은 분석하지 않음 (공개 데이터 없음)
- 전력 용량·안전거리는 현장 확인 항목으로 사람에게 넘김

### 향후 발전 방향

- 진단 범위 확장: 전기·수소 충전에 더해 충전 대기 시간 동안 이용할 휴식·편의시설 배치까지 판단
- 데이터·AI 운영: 수요 변화·충전기 상태 진단을 운영 효율화로 확장
- 고객 경험: 앱으로 충전 대기·고장 안내, 예약 연결
- 주유소를 연료만 넣는 곳이 아닌 일상 생활 플랫폼으로 전환

## 4. Before / After

같은 평가 질문 18개를 개선 전·후로 돌린 결과 (Ollama qwen3, 로컬이라 비용 0원)

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| LLM 판별 일치율 (교정 전) | 53.7% | **85.2%** |
| 코드 교정 건수 (판별 54개 중) | 25 | **8** |
| 요청 분류 정답 | 17/18 | **18/18** |
| 데이터에 없는 숫자 | 0 / 281 | 0 / 300 |
| 질문당 LLM 호출 (평균) | 3.6회 | 3.9회 |
| 응답 시간 중앙값 | 68초 | 79초 |

- 개선 내용: 25개 구 순위 사실 추가, 순위 읽는 법 명시, 판별·우선순위 판단에 생각 모드
- 응답 시간·호출 수가 늘어난 건 생각 모드와 우선순위 판단(호출 1회)을 더했기 때문
- 18개 중 2개(미래주유소·성북구)는 오히려 1~2건 더 틀림 — 최종 판정은 코드 교정으로 확정

## 5. 실행 방법

```bash
bash sh/setup_venv.sh        # 처음 한 번 (.venv 생성, 패키지 설치)
cp .env.example .env         # LangSmith·OpenAI 키 입력 (fake 모드는 없어도 됨)
bash sh/run_agent_fake.sh    # 백엔드 :8100
bash sh/run_frontend.sh      # 대시보드 :8600 (새 터미널)
```

- 접속: http://localhost:8600

| LLM | 실행 명령 | 비용 |
|---|---|---|
| fake (같은 질문에 항상 같은 답) | `bash sh/run_agent_fake.sh` | 없음 |
| Ollama (로컬) | `bash sh/setup_ollama.sh` 후 `bash sh/run_agent_ollma.sh` | 없음 |
| OpenAI | `bash sh/run_agent_openai.sh` | 과금 |

- fake 모드는 경유차 감소를 일부러 1건 틀리게 판별 → 코드가 교정하는 과정 확인용
